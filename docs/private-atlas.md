# Private alternative political atlas

Open **My maps → United Subcontinent — Alternative Political Geography → Open private map**. The map is a separate atlas; opening it preserves the editor draft and the IndexedDB map library. Its password is verified by the server. The map's editorial content and geographic payload are never bundled into frontend JavaScript.

## Local operation

Use `npm run build:vercel` and `npm run preview:vercel -- --host 127.0.0.1 --port 4545`. The Vite server and preview mount `/api/private-atlas`; ordinary static hosting cannot provide authentication. Development also supports this API. The private directory and encrypted dataset are denied by the development file server.

The initial credentials are in ignored `.env.local`. Keep that file private and backed up securely. The three server-only values are `PRIVATE_ATLAS_PASSWORD_HASH` (scrypt N=32768, r=8, p=1), `PRIVATE_ATLAS_SESSION_SECRET` and `PRIVATE_ATLAS_DATA_KEY`. None has a `VITE_` prefix. No plaintext password is stored. Never copy these values into a public repository, browser configuration, client environment variable or screenshot.

The server decrypts `server/private-atlas.enc` using AES-256-GCM after authenticating requests. Signed two-hour session cookies are HttpOnly, SameSite=Strict and Secure in production. Every data endpoint independently checks authentication and responds with `Cache-Control: private, no-store`. Origin checks restrict mutations to the application. Failed password attempts are limited per IP within a running server instance. A public serverless deployment should additionally configure durable platform/WAF rate limiting on this endpoint; an in-memory limiter does not coordinate independent function instances.

## Vercel deployment

`api/private-atlas.mjs` is a Node function, included by the existing Vercel build. Set the same three values as **server-side Secret environment variables** on the deployment. The encrypted file must be included with the function (configured in `vercel.json`). `PRIVATE_ATLAS_ORIGIN` can additionally pin the exact deployment origin. Protect credential backups: possession of the data key permits decryption without the access password. Changing the session secret invalidates all sessions. The app fails closed when server settings or the encrypted payload are unavailable.

This request did not deploy the private atlas or publish its plaintext data. Existing public source datasets are retained unchanged; they do not contain the new private proposal. Authenticated viewers can inspect the atlas and explicitly download the administrative CSV. Any authenticated viewer can also copy data they receive; password protection is access control, not DRM.

## Editorial inputs and regeneration

Private editorial inputs, builder, photograph metadata, build output and geometry audit live in ignored `private/united-atlas/`. Preserve them for future editing. The reviewed `profiles.json` is the canonical editorial input; `profiles.py` is its initial scaffold and should not overwrite reviewed prose. `scripts/build-private-atlas.py` runs the private builder to derive source assignments, district splits, divisions, the 72-tehsil KP review, administrative table and exact geometry. It uses Shapely 2.1 and GeographicLib from the project-local geometry runtime. Run the private `refine.py`, `repair-precision.py`, `areas.py` and `correct-districts.py`, then `scripts/regroup-private-atlas.py`, followed by private `include-shaksgam.py`, `finalize.py` and `compact.py`. The regrouping script is idempotent and preserves a private backup of the earlier 43-province dataset. The finished atlas has 42 provinces, states and union territories. These steps reconcile source-edition seams, normalise shared polygon precision, calculate ellipsoidal areas, validate district splits, attach sourced city/heritage points and verify finished coverage and response sizes. Preserve their topology and audit outputs with the private inputs.

`scripts/private-atlas-photos.mjs` records Commons author/license metadata and preserves reviewed galleries from private `curated-photos.json`; reusable existing shrine photos retain their original attribution. Punjab has five attributed photographs: the Golden Temple illuminated at night, Nankana Sahib, Lahore Fort, Murree and Kartarpur Sahib. Its three proposed official languages are Punjabi (Gurmukhi), Hindi and Urdu; the designation applies only to this fictional scenario. The visible infobox omits flag/emblem and area-method fields, while measurement provenance remains in Research & changes. `node scripts/pack-private-atlas.mjs` encrypts the reviewed payload using the server data key. An initial password is accepted only through stdin if no password hash exists. Verify with `npm run check:private-atlas` and `npm run check:private-atlas-browser`, supplying the test password through stdin. Browser checks use an isolated storage profile and do not alter the user's saved maps.

Province ownership is a fictional partition of retained source editions. The province overview uses shared-edge simplification; finer outlines load through protected requests and replace all province outlines together so neighbouring edges remain aligned. District/tehsil detail is paged through authenticated requests. Source identity, geometry hashes, census year, ownership priority, overlap adjustments and unavailable administrative coverage appear in **Research & changes**. Exact WGS84 polygon area includes source inland waters and is not a verified dry-land-only figure. Forest statistics remain unavailable until a defensible matched aggregation exists. Indian 2011 and Pakistan 2023 populations are not combined into a misleading single-year total.

User-defined populations belong in the optional `hypotheticalDemographics` profile field, separate from real-world `population` and `census`. The packer validates nonnegative integer community counts and derives their total. The panel labels these values as hypothetical and displays lakh/crore counts, calculated shares and scenario density. Its total covers only the supplied groups; it does not infer counts for other communities. These editorial values stay in the encrypted private payload.

United Jammu and Kashmir combines the previously allocated JK, AJK and Gilgit-Baltistan polygons with the existing Natural Earth Siachen polygon. Ladakh–Aksai Chin combines the previously allocated Ladakh outline with the existing Aksai Chin source polygon. The two unions use shared polygon edges; Siachen is assigned to the Kashmir province, and Aksai Chin takes priority over a small GB source-edition overlap. Current administration and disputed-boundary references remain available independently. Shaksgam Valley (called Shaksam Valley in the retained source) is also assigned to United Jammu and Kashmir by unioning the existing Natural Earth polygon; its current-administration context remains available. These are fictional cartographic choices, not surveyed control lines or a resolution of territorial disputes. Unverified district/tehsil coverage in Siachen, Shaksgam Valley and Aksai Chin remains explicitly unavailable. Retained Indian states outside the redesign use their source outlines. The national view initially shows only provinces, states, UTs and capitals; district and tehsil boundaries are optional detail views.
